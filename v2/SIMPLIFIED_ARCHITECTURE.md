# 简化架构方案

## 核心问题

用户问"伊朗局势如何"，系统有 HTTP 工具，但没用上。

**原因**：太多层抽象，阻碍了"需求"和"工具"的直接连接。

## 简化方案

```
用户输入 → Agent → 选择工具 → 返回结果
```

**Agent 的思维过程**：
1. 用户想要什么？
2. 我有什么工具？
3. 哪个工具最合适？
4. 用这个工具
5. 返回结果

## CEO 的真正职责

CEO 不是分类器，而是**理解者 + 决策者**：

```typescript
// CEO 不返回 { type: "query", queryType: "..." }
// 而是返回 { userWant: "...", suggestedTool: "...", reason: "..." }
```

## 实现

CEO.analyzeAndAssign() 应该：
1. 理解"伊朗局势" → 需要**外部信息**
2. 检查工具 → 有 `HTTP` 工具
3. 建议 → 用 HTTP 工具搜索
4. 路由到 → 直接调用 HTTP 工具

不再需要中间层的 CXO 抽象（除非真正有价值）。

## 关键变化

- **去除意图分类**：query/goal/task/script 是人为限制
- **直接匹配能力**：用户需求 → 系统能力
- **工具即能力**：每个工具代表一种系统能力
