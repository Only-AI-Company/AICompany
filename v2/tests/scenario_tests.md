# 不同需求场景测试

## 场景分类

根据系统能力，设计了以下 6 类需求场景：

| 场景类型 | 描述 | 预期 CXO | 工具 |
|----------|------|----------|------|
| 1. 代码开发 | 写代码、技术实现 | CTO | bash, write_file |
| 2. 内容创作 | 写文章、文案 | CMO | - |
| 3. 系统查询 | 查询内部状态 | CEO | query_system_status |
| 4. 外部信息 | 新闻、天气、实时信息 | CEO | HTTP |
| 5. 目标管理 | 设定目标、进度跟踪 | COO | - |
| 6. 脚本执行 | 执行命令、自动化 | COO | bash |

---

## 测试用例

### 1. 代码开发场景

#### 1.1 Python 脚本开发

**用户输入**: "帮我写一个 Python 脚本来处理 CSV 文件"

**预期流程**:
```
[CEO] 分析并分配："帮我写一个 Python 脚本来处理 CSV 文件"
[CEO] 检索记忆：0 个相似任务（首次）
[CEO] 理解：需要 Python 开发能力
[CEO] 决策：外部信息查询 → 否，代码开发 → 是
[CEO] 分配给：CTO
[CEO] 执行：CTO 调用 API Agent 执行
```

**任务完成后**:
```
[TaskReviewer] 存储情景记忆
[TaskReviewer] 提取语义记忆：Python 开发最佳实践
```

#### 1.2 类似任务（应有记忆检索）

**用户输入**: "帮我写一个 Python 脚本来处理 Excel 文件"

**预期流程**:
```
[CEO] 检索记忆：1 个相似任务
  - "Python 脚本处理 CSV 文件" ✅ 成功
[CEO] 检索模式：1 个相关模式
  - "Python 开发最佳实践"
[CEO] enriched context:
  - 历史参考："Python 脚本处理 CSV 文件" → 成功
  - 可用模式：Python 开发最佳实践
[CEO] 分配给：CTO（基于历史成功经验）
```

## 记忆系统作用

### 无记忆系统 vs 有记忆系统

| 场景 | 无记忆系统 | 有记忆系统 |
|------|------------|------------|
| 首次代码任务 | 分配给 CTO | 分配给 CTO |
| 第二次代码任务 | 分配给 CTO | 分配给 CTO，**建议使用上次方法** |
| 代码优化 | 分配给 CTO | 分配给 CTO，**提供优化最佳实践** |
| 文案创作 | 分配给 CMO | 分配给 CMO，**参考历史成功文案** |
| 系统查询 | 返回状态 | 返回状态，**附带历史查询记录** |
| 外部信息 | 调用 HTTP | 调用 HTTP，**记录搜索历史** |
| 目标管理 | 创建目标 | 创建目标，**关联历史目标** |
| 脚本执行 | 执行脚本 | 执行脚本，**使用成功过的参数** |

## 测试检查清单

### 每个场景测试后检查

- [ ] CEO 日志显示"检索到 X 个相似历史任务"
- [ ] CEO 日志显示"检索到 X 个相关模式"
- [ ] enriched context 包含历史记忆
- [ ] 决策考虑了历史经验
- [ ] TaskReviewer 存储了情景记忆
- [ ] TaskReviewer 提取了语义记忆

### 数据库检查

```sql
-- 检查各类任务记忆数量
SELECT task_type, count(*) as count
FROM episodic_memories
GROUP BY task_type;

-- 检查各类模式数量
SELECT memory_type, count(*) as count
FROM semantic_memories
GROUP BY memory_type;

-- 检查记忆置信度分布
SELECT
  CASE
    WHEN confidence >= 0.9 THEN '高 (0.9-1.0)'
    WHEN confidence >= 0.7 THEN '中 (0.7-0.9)'
    ELSE '低 (<0.7)'
  END as confidence_level,
  count(*) as count
FROM semantic_memories
GROUP BY confidence_level;
```
